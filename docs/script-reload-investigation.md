# Live script reload investigation

Target: Steam `Em4.exe`, PE timestamp `0x457425fd`, image size `0xA08000`. Addresses below are virtual addresses for the executable loaded at `0x00400000`. These offsets are not portable to other builds.

## Observed behavior

- Rebinding only command-to-script wrappers caused an access violation after reload. The saved minidump traced a null command name into the entity command-list lookup at `0x00442500`.
- A full rebuild of 111 command scripts, followed by migration of 34 entity command references to the new command-manager tree, kept a Blumenau freeplay session open. Custom vehicle commands disappeared from both existing and newly spawned vehicles.
- A diagnostic vtable hook recorded the engine's command availability checks. Before reload, `VCmdTeste`, `VCmdSiren`, `VCmdAutoSirenOff`, `VcmdFloodLightsOn`, `MoveTo`, and `GoHome` were checked. After reload, the custom commands stopped reaching this check while `MoveTo` and `GoHome` continued. Entity command lists still held valid native command pointers after migration. This places the failure earlier in command discovery or menu assembly.
- A selective attempt stopped only `teste.script`, called the engine's script cleanup, and expected the scheduler count to fall from 111 to 110. That check failed. The game then exited before a replacement script was compiled. The game log ended with `EXCEPTION 3 at .\script.cpp (31): Function call on terminated script`, which indicates a live callback still reached the stopped script. A minidump was saved at `%TEMP%\em4-script-reload-2196.dmp` on the test machine.
- Static analysis of the embedded CINT interpreter identified a likely cause for the failed selective unload. The scheduler cleanup at `0x0074ADE0` calls `G__unloadfile` at `0x00764C50`. That function calls `0x00764800`, which counts functions defined after the target file. When the count is nonzero, CINT reports `Can not unload ... file busy` and leaves the scheduler entry in place. The prior test did not record this count, so the cause still needs a read-only runtime check. The test had already marked the script terminated, and later command callbacks raised the exception above.
- The first two load-before-rebind tests left custom commands visible and the session open, but neither compiled the edited script. The first passed `Scripts/Game/Command/teste.script`; the second passed the active scheduler path `mod:/scripts/game/command/teste.script`. Both yielded `Script file not found` with a blank file name. Disassembly of the engine caller at `0x005E3347` and formatter at `0x0072E760` shows that the loader at `0x0074B150` receives a UTF-16 string. The plugin had declared that argument as an 8-bit string. Converting the scheduler path to UTF-16 fixed compilation during freeplay.
- With the UTF-16 argument corrected, `teste.script` compiled during freeplay and one existing `VCmdTeste` wrapper was rebound. The pre-existing Sprinter executed edited behavior without restarting the session. A Sprinter spawned afterward did not display that command. A read-only memory inventory showed both Sprinters still had a `VCmdTeste` reference: the first used the older native command object, while the new Sprinter used a new object registered by the second compilation. Both objects had the same icon and cursor paths. The manager's name tree pointed to the new object, and its secondary list held the older one. Swapping those manager slots after rebinding restored the older, working native object to name lookup and fixed subsequent spawns in the tested mod.

## Relevant native structures and calls

- Scheduler singleton pointer: `0x00A9A5A8`. Scheduler script count: `scheduler + 0x10`.
- Command manager singleton pointer: `0x00A94C24`. Its name tree begins at `manager + 0x08`; a secondary command list begins at `manager + 0x14`.
- World manager singleton pointer: `0x00A93F18`. An entity command tree begins at `GameObject + 0x1B8`. Each command-list item contains a native command pointer at `item + 0x04`.
- Native command name: game string at `command + 0xE4`, character pointer at `command + 0xE8`.
- Native command initialization: `0x005E3A70`. Native command destruction: `0x005E3970`. Command availability method: `0x005E3130`, vtable slot 6 at `0x009E5EEC`.
- Script stop request: `0x00748640`. Scheduler cleanup: `0x0074ADE0`. Command script load wrapper: `0x0074B150`.
- CINT file count: `0x00BEFBEC`. File table names: `0x00BF0A88 + index * 0x44`. File match: `0x00764980`. Later-definition count: `0x00764800`. CINT `G__reloadfile` merely calls unload followed by load, so it does not bypass the ordering restriction.

## Current safety boundary

The regular `build.ps1` build leaves Ctrl+F7 as a status-only shortcut. `build.ps1 -EnableCommandScriptReload` enables the experimental request path, which requires both `EM4_EXPERIMENTAL_SCRIPT_RELOAD` and `EM4_ALLOW_UNSAFE_SCRIPT_RELOAD_TEST` at compile time. It compiles a second copy of the changed command script, retains the old CINT file and native commands, switches the old wrappers to the new script and qualified class names, then swaps the command manager's tree and list slots. The working native command object remains in the name tree for future spawns. This avoids the known unload failure and preserves entity pointers. The experiment retains compiled files in memory and limits itself to 16 updates per session. Only `Game/Command` files are candidates; `Game/Mission` changes are ignored.

A read-only live inventory found `teste.script` at CINT file index 14 of 111, with 96 files compiled later. It also found 13 native command references on the two active objects, all registered; the selected Sprinter held `VCmdTeste` under group key 32. After the manager-slot change, the plugin log recorded three successive recompilations of `teste.script`, rebinding one, two, and three command objects respectively, and restoring one spawn binding each time. The user confirmed that `VCmdTeste` remained visible and executed the edited behavior on both the original Sprinter and a newly spawned one. This validates the tested script and mod, while other command scripts and class-layout changes remain unverified.
